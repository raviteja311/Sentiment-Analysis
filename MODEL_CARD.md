# Model Card: Tweet Sentiment Classification

Four models for three-class sentiment classification of short English social
media text. This card covers all four; they share a dataset, a preprocessing
path and a label scheme, and differ only in architecture.

**Labels:** `0 = negative`, `1 = neutral`, `2 = positive`. That ordering is fixed
by the dataset and by every artifact here; it is recorded in `src/config.py` and
in `models/roberta/config.json`.

## Models

| Key | Architecture | Parameters | Framework |
|---|---|---|---|
| `lr` | TF-IDF (1-2 grams, 10,000 features) + multinomial Logistic Regression, `saga`, `class_weight="balanced"` | ~30k coefficients | scikit-learn 1.7.2 |
| `lstm` | GloVe-Twitter Embedding(10k x 100, padding masked) → Bi-LSTM(128) → Bi-LSTM(64) → Dense | 1.42M | Keras 3.12 |
| `gru` | GloVe-Twitter Embedding(10k x 100, padding masked) → Bi-GRU(128) → Bi-GRU(64) → Dense | 1.32M | Keras 3.12 |
| `roberta` | Fine-tuned `cardiffnlp/twitter-roberta-base-sentiment` | 125M | Transformers 4.57 |

Keyed as `bert` until the name was corrected; that key still resolves to
`roberta` as a deprecated alias.

## Intended use

Exploratory and educational sentiment scoring of short English text, and as a
reference implementation of a multi-model serving setup. Suitable for
aggregate-level analysis where individual errors wash out.

### Out of scope

- **Decisions about individual people** - moderation, hiring, credit, discipline.
  A model that is right about seven tweets in ten is not a basis for acting on
  any single one.
- **Languages other than English**, and text much longer than a tweet. The
  recurrent models truncate at 80 tokens, the transformer at 128.
- **Domains far from Twitter** - reviews, clinical notes, legal text. TweetEval
  is drawn from Twitter and carries its vocabulary and conventions.
- **Anything that needs the confidence score to be an exact probability.**
  Scores are temperature-scaled, so they are calibrated only approximately: the
  transformer still has a residual expected calibration error near 0.09 (see
  Limitations). Read a 0.95 as "usually right", not as 95 correct calls in 100.

## Training data

[`cardiffnlp/tweet_eval`](https://huggingface.co/datasets/cardiffnlp/tweet_eval),
`sentiment` config.

| Split | Examples |
|---|---|
| train | 45,615 |
| validation | 2,000 |
| test | 12,284 |

Training-split class balance: neutral 20,673 (45.3%), positive 17,849 (39.1%),
negative 7,093 (15.5%).

Preprocessing is versioned (`src/utils/preprocessing.py`), and each artifact
records the spec it was trained with in `models/<key>/preprocessing.json`, which
inference reads, so training and serving cannot disagree.

`glove-v2`, used by the linear and recurrent models: HTML entities decoded
(`&amp;` → `&`, `&lt;3` → `<3`), lowercase, URLs (`http…` and `www.…`) → `<url>`,
email addresses → `<email>`, `@mentions` → `<user>`, hashtags keep the word and
drop the `#` with camelCase split into words (`#NotHappy` → `not happy`),
negation expanded (`can't` → `can not`, `won't` → `will not`, other `n't` →
`not`), emoji become ordinary words (`😍` → `smiling face with heart eyes`),
underscores become spaces, whitespace collapsed. The Keras tokenizer and the
TF-IDF vectorizer are both configured to keep the angle-bracketed placeholders
and `<3` as single tokens, so `<user>` is a different feature from the noun
"user" and the recurrent models can use GloVe Twitter's vectors for `<user>`
and `<url>`.

`cardiff-v1`, for the transformer from its next retrain: what its base
checkpoint was trained on, which is `@mentions` → `@user` and URLs → `http`,
entities decoded, nothing else. No lowercasing and no emoji-to-words, because
the byte-level BPE vocabulary is cased and already knows emoji.

`glove-v1` is the original behaviour: `glove-v2` without the entity decoding,
hashtag splitting and negation expansion. The transformer currently served was
trained with it and keeps receiving it until it is retrained.

### Reproducing

```bash
pip install -r requirements/train.txt
make train-lr && make train-lstm && make train-gru && make train-roberta
make evaluate
```

Training is seeded (`SEED = 42`). The recurrent models initialise their
embeddings from GloVe Twitter vectors (95.8% of the 10k vocabulary is covered),
downloaded on demand; set `SequenceConfig.pretrained_embeddings = None` to train
them from scratch, which costs about 0.03 macro F1 and 0.05 positive-class F1. Retrains land close to their
predecessors: the transformer's 2026-09-24 retrain scored 0.7864 validation
macro F1 against 0.7815 for the run before it, and 0.7124 against 0.7094 on
test. Per-epoch validation scores for the latest run are kept in
`reports/metrics/roberta_training_history.json`.

## Limitations

**The base checkpoint beats our fine-tuning.** `cardiffnlp/twitter-roberta-base-sentiment`
is itself fine-tuned on TweetEval sentiment, and scored as published it reaches
0.7246 accuracy and 0.7240 macro F1 on test, against 0.7109 and 0.7124 for the
checkpoint we fine-tuned from it. Our training run, on the `glove-v1`
preprocessing that lowercases and turns emoji into words, made the transformer
slightly worse. The next retrain uses `cardiff-v1`, the preprocessing the base
checkpoint expects; until it lands, the honest reading of the table is that
fine-tuning has not yet added anything.

**The newer base is not a better starting point.** `twitter-roberta-base-sentiment-latest`,
the same architecture trained by the same group on a larger and more recent
corpus, was scored zero-shot as a candidate replacement. On validation, the
split this project selects on, it reaches 0.7610 macro F1 against 0.7996 for
the current base; on test the two tie (0.7255 against 0.7240). The current
base therefore stays, and no fine-tuning run from the newer checkpoint is
planned. Its smaller validation-to-test gap (4.8 points against 8.1) says it
is less tuned to this dataset's validation distribution, which would matter
for a different dataset but not for this table. It remains one flag away:
`python -m src.training.train_roberta --base-model ... --out-dir ...` trains a
variant into scratch, and `python -m src.evaluate --include-base --base-model
...` scores any checkpoint zero-shot.

**The recurrent models sit between the baseline and the transformer.** Bi-LSTM
and Bi-GRU beat TF-IDF by 5-6 points of accuracy and remain within 0.5
points of each other; any claim that they differ meaningfully is not supported
by these numbers. Both trail the transformer by ~8 points of macro F1.

**The positive class is still their weak spot**, at 0.602 and 0.607 F1 against
0.66-0.68 for neutral, though less so than before masking and `glove-v2` (0.572
and 0.580) and far less so than before pretrained embeddings (0.522 and 0.530).
Positive recall is 0.55 and 0.58: over 40% of positive tweets are still read as
something else, mostly neutral. The transformer does not share this failure
mode (0.709 F1, 0.749 recall).

**Why it happens.** The test split carries a very different class balance
from training - 32.3% negative and 19.3% positive against 15.5% and 39.1% - so
the models are deployed under a substantial label shift. What has helped is
giving the models pretrained meaning, masked padding and better-normalised
text rather than re-weighting their existing predictions; the interventions
below were each measured and, with one exception, rejected.

**Interventions are judged on validation, never on test.** Earlier versions of
this card compared class weights, a decision bias and a label-shift correction
by their test scores. A choice made by reading test scores is a choice fitted
to the test set, and the score reported afterwards no longer estimates
anything. `make experiments` (`src/experiments.py`) therefore reruns all three
reading only the 2,000-example validation split: class weights by retraining a
variant into a scratch directory and comparing validation scores with the
served run, the decision bias two-fold within validation so it is never scored
on the half it was fitted to, and the EM prior estimate without labels. Test is
consulted once, for the table above. Results for the 2026-09-25 artifacts,
each cell before to after:

**Balanced class weights make things worse**, as they did before. The linear
model uses `class_weight="balanced"`; the recurrent models deliberately do not.
Retrained with balanced weights (negative 2.14, neutral 0.74, positive 0.85),
both lose 4-6 points of accuracy and 3-4 of macro F1 on validation, paying on
neutral, the 45% majority, and this time without even the negative-class gain
the earlier test-judged comparison had seen. The shipped artifacts stay
unweighted; `SequenceConfig.class_weight` turns weighting back on for anyone
who wants it.

**A decision bias helps on held-out validation**, which the test-judged
comparison had denied it. A per-class offset on the log-probabilities, fitted
to maximise macro F1 on one half of validation and scored on the other, adds
about 1.5 points of macro F1 and 4-6 points of positive-class F1 to both
models, at a cost of 2-3 points on neutral. The fitted offsets lower neutral
and raise positive, the direction the label shift above predicts. It is
recorded, not shipped: serving it would mean a decision rule other than the
one the results table measures, and that is a change to make in a retrain,
once, rather than as a post-hoc patch on the probabilities.

**EM label-shift correction still hurts**, though less dramatically than on
test, where it once estimated the prior as 77% negative. On validation, whose
class balance is close to training's, it estimates 58% neutral for the LSTM
and 21% negative for the GRU against an actual 43% and 16%, and costs 1-5
points of macro F1. A prior estimate that is wrong on a split that barely
shifted is not one to trust on a split that does.

Note also that the smallest class is not the worst-scoring one. Positive is, for
all three non-transformer models, despite having two and a half times more
training examples than negative - so imbalance was never the main problem here.

**Confidence scores are calibrated, within limits.** They were raw softmax
outputs; the transformer averaged 0.915 confidence at 71.1% accuracy. Temperature
scaling, fitted on validation and measured on test, cut its expected calibration
error from 0.2039 to 0.0865 and the Bi-GRU's from 0.0319 to 0.0238. A residual
ECE near 0.09 on the transformer is still not nothing: read a 0.95 as "usually
right", not as 95 correct calls in 100. The linear baseline and the retrained
Bi-LSTM are deliberately left uncalibrated - see the README - because the
candidate temperature for each gains nothing on validation folds it was not
fitted to; the Bi-LSTM's raw ECE of 0.031 is already the lowest of the three.

**Each model is served with the preprocessing it was trained with.** The
linear and recurrent models were retrained on 2026-09-25 with `glove-v2` and,
for the recurrent ones, padding masks, and record that spec beside their
weights. The transformer is the 2026-09-24 run, trained with `glove-v1`, and is
served with `glove-v1` until it is retrained with `cardiff-v1`. In that run
epoch 2 was the better checkpoint on validation macro F1 (0.7864 against
0.7754) even though validation loss rose from 0.508 to 0.648, which is why
checkpoint selection is on F1 rather than loss.

### What changed in the 2026-09-25 retrain

Three things, all in the code before any model was retrained:

* **Padding is masked.** The recurrent models' Embedding sets `mask_zero`, so
  the pad vector no longer runs through every step after the text ends and a
  representation no longer depends on how much padding follows it. A text that
  tokenizes to nothing is given one out-of-vocabulary token instead of an
  all-padding row.
* **`glove-v2` preprocessing.** HTML entities are decoded, so `&amp;` and
  `&lt;3` stop reaching the models as the words "amp" and "lt"; camelCase
  hashtags are split into words; and negation is expanded so `can't` arrives
  as `can not` rather than as `can`. The TF-IDF vocabulary keeps `<3`.
* **The base checkpoint is a baseline.** `python -m src.evaluate --include-base`
  scores the transformer's base checkpoint as published, and the table shows
  it. That row is what exposed the fine-tuning result above.

On test the retrain moved the linear model from 0.5768 to 0.5825 macro F1, the
Bi-LSTM from 0.6181 to 0.6304 and the Bi-GRU from 0.6223 to 0.6300; every
gain came from the positive class (F1 0.554 to 0.567, 0.572 to 0.602 and 0.580
to 0.607). `make behaviour` tells a more mixed story: all three models now read
`<3` as positive (the LSTM and GRU did not), but negation checks are still
mostly failed (2, 1 and 2 of 5), and the GRU, which passed all five before,
now flips only two. A bag of words, or a small recurrent model, can be handed
the word `not` and still not use it; the checks exist to say so rather than to
let the aggregate numbers imply otherwise. The transformer passes all 18.

**Test-set scores are the honest ones.** An earlier version of this project's
documentation claimed 85-95% accuracy across these models. Those figures
corresponded to nothing measurable; the table above supersedes them.

**Temporal and topical drift.** TweetEval predates current slang, events and
platform conventions. Performance on recent text will be lower than the table
suggests.

## Where the weights live

The large weights are hosted on the Hugging Face Hub at
[RAVITEJA311/sentiment-analysis-models](https://huggingface.co/RAVITEJA311/sentiment-analysis-models),
not in the git repository. `make fetch-weights` downloads them. The Logistic
Regression pipeline and the tokenizers are small enough to stay in git.

## Provenance

Every score here is regenerated by `make evaluate` from the committed artifacts,
and `reports/metrics/<model>.json` records the hyperparameters, split sizes,
class distribution and preprocessing spec behind it. `models/remote_manifest.json`
pins the Hub commit and the digest of every fetched weights file, so the
weights a score was measured on can be told apart from any later publish.
Numbers in this card should never be edited by hand - regenerate them.
